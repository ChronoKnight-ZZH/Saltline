> 对象：`src/world/level/tidegate.js`（新图 TIDEGATE，冷链东堤）
> 基线：分支 `feat/tidegate-level`，Step 1–3 提交 `85aa053` / `2f7d51f` / `8b264a0`；地图卡片流程在 `feat/map-select`（`3dc852d`）

## 1. 定位：这张图补的是什么

原图 SALTLINE 是“集装箱堆场 + 三台中继 + 码头小船”，特点是大平层、长视线、掩体密集。它缺两样东西：

1. **垂直玩法**：整张图只有地面一层，玩家没有“先上高处看局势、再从高处打下去”的路。
2. **室内/室外切换**：没有真正的室内空间，天气系统（雨、雾、天光）全部作用在同一层空气里。

TIDEGATE 的设计目标就是补上这两点，同时保持原图的枪感与节奏：

- **一条 4.8 m 高的栈桥**贯穿码头，配两段可通行的金属梯（上升 + 北端下行），构成“地面 → 桥面 → 地面”的闭环。
- **一间可进入的冷库**（6.2 m 墙 + 8.5 m 屋脊 + 4 个天窗），提供室内交火、室内混响、室内雨滴抑制，并在天窗落下光柱。
- 三台中继分布在 **堆场 / 冷库北侧 / 栈桥中段**，强制玩家把地面、室内、高处三种空间都用一遍。

与原图的差异是“加维度”，不是“换皮”：分区、掩体密度、敌人配额都按同一套 DSL 与同一套物理碰撞重建，原图的构图、性能与操作手感不受影响。

## 3. 垂直结构

### 3.1 栈桥（6 段连续 `catwalk`）

| 段 | x | z | y |
| --- | --- | --- | --- |
| 1 | 26 | 9.2 | 4.8 |
| 2 | 26 | 6.2 | 4.8 |
| 3 | 26 | 3.2 | 4.8 |
| 4 | 26 | 0.2 | 4.8 |
| 5 | 26 | -2.8 | 4.8 |
| 6 | 26 | -5.8 | 4.8 |

接缝必须首尾相接（相邻段 z 间隔 3.0 = 段长），因为可行走面依赖 mesh raycast，接缝 > 0.5 m 会掉下去。

### 3.2 两段梯（上升 / 北端下行）

`stairs_metal` 单跑只升 2.4 m，所以 4.8 m 必须两跑 + 中间平台：

| 位置 | 调用 | 高端 y | 落点 |
| --- | --- | --- | --- |
| 南端上升 1 | `stairs(26, 16, HALF_TURN, 0)` | 2.4 | 中台 |
| 南端上升 2 | `stairs(26, 13.2, HALF_TURN, 2.4)` | 4.8 | 桥面 |
| 北端下行 1 | `stairs(26, -8.9, -HALF_TURN, 2.4)` | 4.8 → 2.4 | 中台 -10.4 |
| 北端下行 2 | `stairs(26, -11.9, -HALF_TURN, 0)` | 2.4 → 0 | 梯脚 -13.4 |

下行段配 `slabAndCollide(..., -10.7, -9.4, 2.4, 2.48, "metal")` 作为中间平台，梯脚补 `hazard_stripes`（`hz(24.4, -13.7, 27.6, -13.3, 0.004)`）。

**踩过的坑**：`stairs` 的 `yaw` 决定高端朝向。从高端一侧接近会直接撞上 2.4 m 立面 —— 玩家必须绕到梯脚再上。回放验证时在这个坑上卡过两次，写入设计约束（见 §9 第 4 条）。

### 3.3 冷库壳体

| 项 | 值 |
| --- | --- |
| 墙体 | 0.3 m 厚，6.2 m 高 |
| 屋脊 | 8.5 m（双坡顶） |
| 天窗 | 4 个，落在屋脊两侧 |
| 入口 | 南侧 + 东侧两处门洞 |
| 室内盒 | `min(6, 0, -30)` / `max(18, 6.2, -4)` |

## 4. 动线与目标

### 4.1 关键坐标

| 元素 | 坐标 | 说明 |
| --- | --- | --- |
| 出生点 | `(-33, 0, 4)`，yaw `-π/2` | 面向闸口内侧，第一眼看到龙门吊与冷库 |
| 中继 A | `(-4, 0, 12)` | 堆场中央，地面层 |
| 中继 B | `(12, 0.23, -20)` | 冷库北墙角，室内外交界 |
| 中继 C | `(25, 4.8, -6.2)` | 栈桥中段平台，高处 |
| 撤离点 | `(28.5, 0, 20)`，半径 2.5 | 与 `backdrop.extractionPoint(30, 0, 20)` 对应的接驳船 |

三个中继顺序自由，但空间上强制三种打法：A 需要穿越堆场掩体、B 需要摸进冷库北端、C 必须上栈桥。

### 4.2 45° 视角下的路径形状

出生 → 闸口 → 堆场东侧掩体链 → A → 冷库南门 → 冷库内部 → 北门 → B → 码头空地 → 南梯 → 桥面 → C → 下行梯 → 码头北段 → 撤离。

垂直曲线（实测，见 §8.2）：

```
0 → 1.40 → 2.60 → 4.60 → 4.85（桥面）→ 3.80 → 1.20 → 0
```

### 4.3 引导（不靠 UI 指路）

- 桥面 / 中台 / 梯脚三处向下箭头：`(26, -7.9)` @ y 4.786、`(26, -9.9)` @ y 2.486、`(26, -16.2)` @ y 0。
- 地面用 `decal` 铺导引贴花，沿主通路指向下一段空间，避免玩家在 60×60 的堆场里迷路。
- 梯脚 hazard 条纹是“这里可以下/上”的唯一视觉信号，因此颜色与宽度必须和梯子同宽。

## 5. 战术层配额（当前实际值）

| 类别 | 总数 | 分布 |
| --- | --- | --- |
| `coverPoints` | 48 | yard 34（含 10 个箱顶）/ coldstore 6 / quay 8 |
| `enemySpawns`（地面） | 26 | yard 13 / coldstore 6 / quay 7 |
| `enemySpawns`（空中） | 17 | yard 7 / coldstore 4 / quay 6 |
| `interiorBoxes` | 1 | 冷库 |

配额设计口径：

- **箱顶掩体 10 个**是这张图的关键：玩家站上 2.4 m 集装箱后能俯视堆场，敌人也会用箱顶当高位点。
- **冷库 6 地面 + 4 空中**：室内必须能打起来，否则这栋楼只是穿场而过。
- **码头 8 掩体 / 7 地面**：码头是长视线区，掩体少是故意的，逼玩家用栈桥或烟雾。

### 5.1 构建期断言

`auditNav()` 在关卡构建末尾逐点检查 `nav.isWalkable`：出生点、48 个掩体点、43 个出生点全部要落在可走格上，失败时打印坐标清单。当前 64 点全绿。这条断言比“肉眼看没卡住”可靠：AI 出生点落在不可走格会被 2 m 环形搜索静默挪走，表现是“敌人从墙里出来”。

## 6. 光照与环境

### 6.1 主光

| 参数 | 值 |
| --- | --- |
| `SUN_LIGHT.dir` | `(0.916, 0.225, 0.331)` |
| `SUN_LIGHT.intensity` | 9 |

方向刻意压低（y 分量 0.225），让长影子横穿码头，栈桥与冷库在码头面上留下可读的投影，强化“高处”的空间感。

### 6.2 冷库室内

- **4 盏点光**：沿室内长轴分布，负责把货架与地面提亮到“能看清敌人轮廓”的程度，同时保持整体比室外暗。
- **4 根天窗光柱**（Step 3）：`CylinderGeometry(1.5, 2.3, 5.98, 14, 1, true)` + `MeshBasicMaterial{ opacity .055, AdditiveBlending, depthWrite:false, side:DoubleSide, fog:false }`，几何参数与 `skylights()` 数据同源。
- 光柱只加亮空气、不参与深度，做法对齐 `helicopter.js` 的体积锥，避免把货架挡成贴纸。

### 6.3 室内判定（`interiorBoxes`）

引擎用这一条 AABB 回答“相机/玩家是否在室内”，并驱动：

| 消费点 | 作用 |
| --- | --- |
| `render/renderer.js` | 相机在盒内时切 `interiorEnv` 环境贴图并压环境光强度 |
| `render/postprocessing.js` | 体积光 `uBoxMin/uBoxMax/uBoxDust`，室内空气灰尘更高 |
| `world/ground/ground.js` | 盒内不生成雨滴涟漪（否则冷库里会“下雨”） |
| `audio/audio.js` | 盒内平滑切室内混响 |
| `app/runtime.js` / `renderer.js` | 反射探针放在第一个盒中心 |

**已知限制**：除 `ground` / `audio` 遍历全部外，其余三处只读 `[0]`。多盒只对“雨 + 混响”生效，环境贴图、体积光、探针永远用第一盒。要真做多室内，需要“每盒一个探针 + 按所在盒切换”，属渲染改动，需连原图一起回归。

**建议的最小修正**：把盒从外墙外表面收进墙体净空（墙厚 0.3），让室内外切换发生在门洞而不是墙面上：

```js
interiorBoxes: [
  { min: new Vector3(6.3, 0, -29.7), max: new Vector3(17.7, 6.0, -4.3) },
],
```

### 6.4 与天气系统的兼容

TIDEGATE 不新增天气预设，沿用 `environment-presets.js` 的 4 时段 × 4 天气。需要注意的只有两点：

- **午夜 + 无闪电**会启用巡逻直升机（`helicopter.js`）。它**跟随玩家绕飞**（`targetX/Z` 由 `player.pos` 加偏移算出），不是固定摆设，所以不需要按地图挪位；要验的是光柱与冷库屋顶、栈桥面的遮挡关系。
- **暴雨**下码头面反射最强，栈桥 4.8 m 高处的雨天可视度会比地面好，这是这张图的天然优势，不要用雾把它抹平。

## 7. DSL 约定与踩坑

| API | 真实签名 | 备注 |
| --- | --- | --- |
| `stairs` | `stairs(x, z, yaw?, y?, opts?)` | `yaw` 决定高端朝向，走错一侧直接撞立面 |
| `catwalk` | `catwalk(x, z, yaw?, y?, opts?, rails?)` | 段长固定，必须首尾相接 |
| `place` | `place(name, x, z, yaw?, opts?, y?)` | 第三参是 yaw，不是 y |
| `decal` | `decal(name, size, x, y, z, face?, rot?)` | y 在 size 之后 |
| `label` | `label(text, size, x, y, z, face?, opts?)` | **没有 rot**；`opts.color=white/black/yellow`、`font=sans/stencil`、`distress` |
| `slab` | `slab(mat, x0, y0, z0, x1, y1, z1)` | 两点式 |
| `box` | `box(mat, w, h, d, x, y, z)` | 尺寸在前、中心在后 |
| `col` | `col(x0, y0, z0, x1, y1, z1, surface?, opts?)` | 碰撞盒，`opts` 里可挂 `noMerge` |

另外两条工程约定：

1. **要动的物体必须 `dynRoot` 或 `noMerge`**：中继、卷帘门、吊具若被合批进 `level-merged`，`object` 引用会失效，交互直接哑掉。
2. **桥面必须整段连续 `catwalk`**：可行走面靠 raycast，中间留缝就掉。

## 8. 实测数据

### 8.1 性能对照（`?bench=1`，812×847，quality high，dpr 1.25）

| 关卡 | avg | median | p99 | fps | draw calls | tris |
| --- | --- | --- | --- | --- | --- | --- |
| TIDEGATE | 43.7 ms | 33.3 | 49.7 | 23 | 466 | 1.13 M |
| 原图 level | 47.0 ms | 33.5 | 84.3 | 21 | 215 | 1.86 M |

median 33 ms 是被 vsync 卡住的上限。TIDEGATE 三角面少 40%，draw call 高是因为材质组更碎。结论：**新图不比原图慢，p99 更稳**。

### 8.2 完整通关（确定性回放）

- 37 个路点全过；y 曲线 `0 → 1.40 → 2.60 → 4.60 → 4.85 → 3.80 → 1.20 → 0`，两跑台阶吸附与 6 段桥面接缝都成立。
- A / B / C 三点在 2.4 m 内触发，`game.state` → `complete`，结算页 `SALTLINE IS DARK / CLEAN / TIME 00:55`。
- **验证口径**：自动化环境页面 `hidden`，rAF 停摆且 CDP 输入被宿主拒绝，没有“真按住 W 走位”。替代做法是固定步长 `dt=1/60` 顺序调用 `input.update → game.update → player.update`（真实胶囊体、真实 `moveCapsule`、真实台阶），只由脚本设 `yaw` 与 `move.y` 指路；中继用引擎自带 `debugCut()`（同一 `me()` 计数路径）。**E 键长按本身未验证**。

## 9. 已知风险（4 条）

1. **导航可达性**：出生点/掩体落进不可走格会被 2 m 环形搜索静默挪走，体感是“敌人从墙里出来”。已用构建期 `auditNav()` 兜住。
2. **合批与 `noMerge`**：需要交互的物体被合批后引用失效，交互哑掉且无报错。
3. **4.8 m 栈桥的地面判定**：接缝 > 0.5 m 会掉；已用真实胶囊体走完上升段→桥面→下行段验证。
4. **上下梯的方向**：`stairs` 的 `yaw` 决定高端朝向，从高端接近会撞立面。

## 10. 入口与菜单集成

| 入口 | 行为 |
| --- | --- |
| `?map=tidegate` | 以 TIDEGATE 作为关卡开局（默认仍需选天气） |
| `?map=tidegate&autostart=1&noaudio=1` | 直接进入游戏，跳过所有菜单 |
| `?show=tidegate&q=high&noaudio=1` | 展示模式（自由相机巡览） |

菜单流程（`feat/map-select`）：

```
标题 Deploy/Enter → 地图卡片（SALTLINE / TIDEGATE）→ 天气 lane 选择 → 开局
                ↘（该图无天气预设时，确认地图即直接开局）
```

换图会重载一次页面（关卡在启动期装配，运行时无法原地替换），带 `&brief=1` 让重载后直接落到天气选择。暂停菜单的 `Return to title` 会把整局复位（中继归零、计时清零、玩家回出生点）后回到标题，而不是原地重开。
