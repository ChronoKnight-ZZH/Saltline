## 实现方式：inverted hull（背面描边，屏幕空间定宽）

没动你那套自写 HDR 后处理管线（往里塞 OutlinePass 风险大），而是给每个敌人挂一层红色外壳：

- **新文件 `src/render/enemy-outline.js`**：遍历 `enemies.list`，对每个存活敌人在其模型根 `enemy.rig.group` 的子树里，为每个"实心" Mesh/SkinnedMesh 在**原父节点**下生成一层红色 `BackSide` 外壳。外壳局部变换与本体完全一致，**厚度由顶点着色器给**：顶点沿"视图空间法线在屏幕上的投影方向"外推固定像素数（`OUTLINE_PX`），所以 3m 和 40m 都是同样粗细的一圈边。外壳挂回原父节点而不拍平层级，SkinnedMesh 共享原 skeleton 与 bindMatrix，轮廓跟着骨骼动画（腿、旋翼、编号牌）一起动。
  - 不能靠"整体放大 1.07 倍"或"世界空间膨胀"来做：SkinnedMesh 在 `AttachedBindMode` 下每帧把 `bindMatrixInverse` 重算为自身世界矩阵的逆，顶点最终回到世界空间，`mesh.scale` 被完全抵消 —— 外壳会与本体严格重合，本体不给侧面就一条边都看不到。这就是早期版本"只有桨盘、灯光变红、本体没有轮廓"的原因。
  - 世界空间定距膨胀（把顶点沿法线推固定米数）虽然能出边，但厚度随距离剧烈变化：近处把细腿整根吞成红色、远处又细到看不见，所以最终改成屏幕空间定宽。
  - 发光件（`glow` / `lens`）与透明件（桨盘糊影 `disc`、光锥 `cone`、贴花）不参与描边：按 `geometry.groups` 对应的材质判断，材质 `transparent === true` 或 `name === "emissive"` 的三角形不拷进外壳几何体；整个网格都是这类材质时干脆不生成外壳。否则红边会变成一圈红色光斑或整片红盘。

- **接入 `runtime.js`**：import 后在 environment 装配后 `createEnemyOutline(context)`，主循环在 `enemies.update` 之后加 `updateSystem("outline", p)`。失败 try/catch 不崩游戏。

## 你提的两个要求怎么落地

| 要求 | 实现 |
|---|---|
| **视角内可见** | 敌人对象本身没有 `group`，模型根是 `enemy.rig.group`；外壳作为其子节点存在，敌人 `rig.group.visible = false`（未激活/已沉没）时整棵子树连同描边一起不渲染。单个外壳网格关闭了 `frustumCulled`（蒙皮包围球和实际体积对不上，开着会在画面边缘误裁），开销由可见性 + 视距控制。 |
| **视距裁剪** | 每帧算敌人到 `context.camera.position` 距离：>60m 隐藏；48–60m 之间透明度线性渐隐到 0。不是硬切，是平滑淡出。 |

可调参数在 `enemy-outline.js` 顶部：
- `OUTLINE_COLOR = 0xff3030`（红边颜色）
- `OUTLINE_PX = 2.4`（描边宽度，CSS 像素；屏幕空间定宽，与距离、模型尺寸都无关）
- `MAX_DIST = 60` / `FADE_START = 48`（裁剪距离）
