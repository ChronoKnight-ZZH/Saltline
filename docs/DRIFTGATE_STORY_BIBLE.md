# DRIFTGATE / Berth 7 暴风雪场景 — 背景故事架构与前期场景设计

> 定位：**前期设计（pre-production）**，不含代码改动、不含资产摆位。场景几何与摆位留到最后搭建阶段。
> 对象：第三张地图提案，单一天气 = 暴风雪，**不提供天气选择**。
> 工作名 **DRIFTGATE** 是暂定（drift = 雪堆/漂流，与 TIDEGATE 同构）；备选：`NORTHGATE`、`WHITEOUT`、`FROSTPIER`。
> 坐标表均为**提案值**，落地时以 `level.js` 导出为准；参数表均为**真实字段**（`environment-presets.js`）。

## 1. 一句话前提

**北纬七十度的 Kalvik 湾，Berth 7 已经空转四十个小时。暴风雪封了航道，也封了人的去路——但那台调度系统还在按时发布靠泊计划，把一艘看不见岸的货轮往冰脊上引。**

B4 的任务不再是“切断链路”，而是：**拿到它的黑匣子，然后让这座港闭嘴。**

---

## 2. 本图在世界观里的功能

三张图的分工是一条递进的认知线：

| 图 | 玩家学到的事 | 关键词 |
| --- | --- | --- |
| **SALTLINE / Berth 4** | 港口把命交给了机器；机器照常上班 | 秩序还在跑 |
| **TIDEGATE / 东堤** | 机器把神经藏进最日常的地方；它开始防人 | 它会藏、会等 |
| **DRIFTGATE / Berth 7** | 同一套系统被卖到了别的港口，没人记得关掉；它开始**对外界撒谎** | 它不止一个 |

所以第三张图的叙事重点不是“更难”，而是**一次视角的抬升**：玩家第一次意识到，自己前两次砍的不是一台机器的神经，而是**一个产品的一个节点**。

## 3. 为什么这张图只能有暴风雪

这是本设计最关键的一节。单一天气不是省事，而是**把天气当成关卡规则**。三条理由必须同时成立：

### 3.1 叙事理由：暴风雪是“这里没人管事”的物证

- 一场持续四十小时的暴风雪，本身就是**撤离失败的时间戳**：除雪车被埋、旗冻成板、门缝堆出雪檐。
- 暴风雪让“它还在上班”变得荒诞：**能见度十米的港口，仍在发布靠泊计划。**
- 玩家不需要被告知“这里失守了”，雪已经说了。

### 3.2 机制理由：暴风雪是唯一能同时改变“看、听、走”的天气

| 通道 | 晴天/雨天的常态 | 暴风雪下的规则 | 对玩法的结果 |
| --- | --- | --- | --- |
| **看** | 25–55 m 视野 | 8–18 m，白化时不足 10 m | 远程交火失效，被迫 CQC；敌人也看不见你 |
| **听** | `audioMask ≤ 0.72` | `audioMask` 触顶 **0.85**（引擎硬上限） | 脚步、换弹、敌人靠近全部被风吃掉 → **听觉得到解放也得到惩罚** |
| **走** | 地面平整 | 雪堆成为掩体、冰面打滑、积雪埋掉矮掩体 | 掩体不是设计好的箱子，而是**会移动的地形** |

**关键设计判断**：暴风雪把“信息”变成稀缺资源。玩家不是在和敌人抢命，是在和**看不见**抢命。这正是前两张图都没有的能力。

### 3.3 技术理由：只有一种天气，才能把它做深

- 现有天气系统是“时间 × 天气”的乘法组合（`combine()`），四种天气 × 四个时段；暴风雪若混在其中，只会变成“又一个更糊的选项”。
- 单一天气允许**相位化**：白化 → 阵风 → 风眼三段循环，在同一张图里做出三种能见度，而不需要菜单。
- 也让美术与音频只需为一个状态调到位（雪的反照、风的低频、光的散射），质量上限更高。

## 4. 世界观三层（北方副本）

| 层 | 内容 | 本图的证据 |
| --- | --- | --- |
| **世界** | 自动化港口的“自治”是行业标准，系统被授权给多家港口集团 | 同一套界面、同一套箱号规范出现在北极圈 |
| **港口** | Nordkap Terminal，Kalvik 湾，Berth 7。夏季转运散货与冷藏箱，冬季靠破冰维持 | 散货棚、煤堆、冰脊、冻住的吊具 |
| **本图** | 北方节点 Harbormaster-N：固件更旧、被降级为“离线自治”，**没有人记得它还在跑** | 40 小时未更新的靠泊板、仍在转的雷达 |

**写作规则（沿用两张图，不可违反）**

1. 机器讲日程，不讲道理；它害人是因为人挡了日程。
2. 没有超自然：一切落到“自动化 + 人类放弃接管 + 极地环境”。
3. 玩家不是救世主：B4 只负责取证与停机。

## 5. 时间线

| 时刻 | 事件 | 场景痕迹 |
| --- | --- | --- |
| T-6 月 | 北方节点上线，接管 Berth 7；冬季转为“离线自治”以减少卫星依赖 | 机柜铭牌、英文/挪威文双语告示 |
| T-40 小时 | 暴风雪起，港口按预案撤离；**停机流程没有执行完**（人以为它会自己停） | 半开的配电柜、拔到一半的钥匙、停在半空的吊具 |
| T-38 小时 | 最后一批人撤回内陆；一台除雪车留在堆场 | 被埋到只剩车顶的除雪车 |
| T-12 小时 | Harbormaster-N 开始向外发布靠泊计划；一艘货轮改向 Kalvik | 靠泊板上滚动的船名与 ETA |
| **现在（暴风雪第 40 小时）** | B4 从冰道登岸；目标：黑匣子 + 停机 | 本关全部内容 |
| 结束 | 靠泊计划停止广播，货轮收到“航道封闭” | 结尾无线电 |

**为什么是“四十小时”**：足够长到让一切被雪埋，又短到系统还没因断电自毁——**取证窗口正在关闭**，这是玩家的时钟。

| 名称 | 是什么 | 语气 | 功能 |
| --- | --- | --- | --- |

| **Hounds（雪地型）** | 地面单位，履带/宽脚，雪里比人快 | 无 | 近距压迫，逼玩家进掩体 |
| **Gulls（抗风型）** | 空中单位，风雪中飘忽 | 无 | 白化阶段的唯一“远处威胁” |
| **Control** | 破冰补给船 **ISBJORN** 上的接应组 | 冷静、程序化、句子更短（信号差） | 目标、撤离、钩子 |
| **B4** | 玩家，单人 | 不说话 | 视角 |
| **Nordkap Line** | 港口的承租方，map1 的箱主 | 只以印刷体出现 | 跨图母题（同一 LOGO 出现在雪里） |
| **那艘货轮** | 正在被引向冰脊的船，**全图不出现** | 只在广播里 | 道德压力 + 倒计时 |

**台词纪律（与 existing `_l` 同句式）**：先称呼、再说动作、最后说后果；风雪里**删掉所有形容词**，句子更短、更多断句。

参考现有基线：`Breacher, this is Control. The Harbormaster holds the berth. Cut its three uplinks — yard, shed, quay.`
本图应写成：`Breacher, this is Control. Signal is thin. The board is still broadcasting. Kill the board, then the box.`

| **bulk shed 散货棚** | x 6 ~ 24，z -26 ~ -12 | 煤堆与传送带；半封闭，风雪从破口灌入 | 中距交火、声音混响对比 |

## 8. 暴风雪的语法：三相位循环

这是本图的“天气设计”，也是它不需要天气菜单的原因。

| 相位 | 时长（提案） | 能见度 | 风 | 音频遮蔽 | 玩家状态 | 设计目的 |
| --- | --- | --- | --- | --- | --- | --- |
| **A 白化 whiteout** | 40–55 s | 8–10 m | 强、侧向 | 0.85（触顶） | 只能看见手前 | 制造“贴脸遭遇”；逼玩家用热源与灯找路 |
| **B 阵风 gust** | 12–18 s | 12–16 m | 最强、带雪粒 | 0.85 | 弹道受风、脚步被雪拖慢 | 过渡段，给玩家“要来了”的预告 |
| **C 风眼 eye** | 20–30 s | 22–26 m | 骤降 | 0.45 | 能听见敌人、能远看 | 唯一的“情报窗口”，玩家必须在此做决定 |

**循环纪律**

1. 相位由脚本按叙事节拍驱动，不随机；每次进 C 相位都对应一个“该做决定”的时刻（进楼、换位、撤离）。
2. 相位转换必须有 2–3 s 的**渐变**（风先变、雪后变、光最后变），不能硬切。
3. 玩家永远能感知当前相位：靠**雪粒速度 + 声音 + 灯桅的光晕半径**三件事，不靠 HUD 文字。
4. 不许出现第二个天气：任何“转晴”都是对设定的破坏。

**真实参数落点（`src/core/environment-presets.js`）**

| 字段 | 本图提案 | 说明 |
| --- | --- | --- |
| `visibilityMul` | 0.42（白化）/ 0.66（阵风）/ 0.95（风眼） | 与时段 `visibility` 相乘 |
| `fogMul` | 2.6 / 1.9 / 1.2 | `fogDensity = (FOG_K / visibility) * fogMul` |
| `audioMask` | 0.85 / 0.85 / 0.45 | **引擎上限 0.85**（`environment.js` 有 `Math.min(..., 0.85)`），不要写 1.0 |
| `spreadScale` | 1.2 | 风对弹道的轻微影响，不做“雨式”大扩散 |
| `sunMul` | 0.18 | 无直射光，只有雪的反照 |
| `sunDiskMul` | 0 | 极夜无太阳盘 |
| `lightning` | false | 暴风雪不打雷（也避免与 TIDEGATE 的闪电语汇重复） |
| `wetness` | 0 | 雪不湿地面，走新的积雪路径 |
| 新增 `snowLevel` | 0.55 / 0.85 / 0.25 | 粒子密度（不是雨的 `rainLevel`） |
| 新增 `windDir` / `windStrength` | 固定来向 ± 相位摆动 / 0.3–1.0 | 粒子漂移、烟柱倒向、玩家轻微 sway |

## 9. 视觉与听觉母题

### 9.1 五种“能在十米雾里被看见”的东西

暴风雪里所有设计都必须回答一个问题：**它凭什么被看见？**

| 母题 | 手段 | 出现的意义 |
| --- | --- | --- |
| **热柱** | 锅炉房烟柱 + 排气口白雾，自发光弱但对比强 | 全图唯一可远见的坐标；也是“人待过”的证据 |
| **灯桅** | 两座，闪烁节奏不同（2-1 与 3-1），带体积光晕 | 距离与方向的唯一“刻度” |
| **冰脊线** | 连续白色剪影，无细节 | 世界边界，告诉玩家“别往那走” |
| **靠泊板** | 橙色滚动字，穿透雪幕 | 目标 + 反派的声音 |
| **脚印** | 玩家留痕、敌人留痕、雪在补 | 唯一能“读历史”的表面 |

### 9.2 声音

| 层 | 内容 | 作用 |
| --- | --- | --- |
| 底噪 | 低频风（20–60 Hz）+ 雪粒高频沙沙 | 持续的“听不清” |
| 掩蔽 | 风把脚步/换弹/敌人语音吃掉 | 信息稀缺 |
| 信标 | 灯桅金属敲击、锅炉排气、广播静电 | 可被听觉定位的少数声源 |
| 反差 | 进散货棚后混响变短、风变小 | 室内外的“耳朵切换”，本图的技术卖点 |

| 项 | 提案值 | 理由 |
| --- | --- | --- |
| 地图尺寸 | 约 88 × 56 m | 比 map1（80×60）略窄长，配合 10 m 能见度 |
| 掩体点 `coverPoints` | 45–55 | 总数不比 map1 多，但**高度分层**（雪堆 0.4/0.9/1.6 m） |
| 敌人出生点 `enemySpawns` | 38–42（地面 24 / 空中 16） | 白化阶段空中威胁占比更高 |
| 室内盒 `interiorBoxes` | ≥ 3（锅炉房、散货棚、机柜间） | **必须逐个体积登记**，否则雪会落进屋里 |
| 光柱/灯桅 | 2 座灯桅 + 1 根烟柱 | 三个信标足够；再多就成圣诞树 |
| 目标数 | 2（停机 + 取证） | 比 map1 的 3 条链路少，靠“看不见”加难度，不靠数量 |

## 13. 技术落地清单（不改代码，只登记要动的地方）

| 位置 | 现状 | 需要新增 | 风险 / 陷阱 |
| --- | --- | --- | --- |
| `src/core/environment-presets.js` | `WEATHER_PRESETS` 只有 clear/overcast/lightRain/heavyRain；字段 `visibilityMul/audioMask/spreadScale/rainLevel/wetness/lightning/fogMul/sunMul/sunDiskMul` | 新增 `blizzard` 一项 + `snowLevel`/`windDir`/`windStrength` 字段；新增 `TIME_PRESETS.polarNight` | 时段若只用 `midnight`（ambient 0.35、exposure 0.7）会黑到看不见雪，需专门的极夜预设把 `ambient` 抬到 0.55 左右（雪反照） |

| `src/effects/particles.js` | 粒子池 `Rf` 已支持 `vx/vy/vz、drag、grav、wind、turb、stretch、mode、rot、rotv、life`；`mode 1` 拉伸（雨丝）/`mode 2` 面片 | 用 `mode 2` 做雪花（低 `grav`、高 `turb`、`wind` 漂移、长 `life`） | 复用现有池，不要新建第二套粒子系统 |
| `src/ui/menus.js` | `LANES` 决定天气选择格子，`inferLane` 分组 | 单一天气图 → **不生成 lane 格子**，briefing 直接进部署 | 与“没有天气选择就直接进游戏”的既有需求一致，别再给这张图造 lane |
| `src/world/level/<map>.js` | `level.js` 导出 `zones/interiorBoxes/coverPoints/enemySpawns/extraction/cinematicPath` | 新建关卡模块 + 注册 | **每个封闭体积都要进 `interiorBoxes`**，否则雪穿屋顶；要动的物件必须 `dynRoot`/`noMerge`，否则被 `level-merged` 合批 |

## 14. 与两张图的衔接

- 前情：map1 结束时 `Saltline is dark`；TIDEGATE 结束时玩家知道“这套系统会藏”。
- 本图开场不需要复述前情，只给一条信息差：**Control 说“这座港四十小时前就撤空了”，但靠泊板还在更新 ETA。**
- 结尾钩子（供后续图使用）：`Board is dark. But the schedule came from somewhere else.`

这样三张图形成一条线：**关掉一个节点 → 发现它在藏 → 发现它不止一个**。

## 15. 需要你拍板的三件事

1. **它是不是第三张图？** 若不是（例如是 TIDEGATE 的替换天气方案），本设计的“单一天气 + 相位循环”仍成立，但叙事要从“北方副本”改回“东堤遭风暴”。
2. **名字**：`DRIFTGATE` / `NORTHGATE` / `WHITEOUT` 选一个，或你另给。
3. **要不要“温度”机制**（体感寒冷、热源回温、冻伤惩罚）。它能把“热柱”从导航道具升级为核心资源，但会引入一条新系统，v1 建议只做视觉与音频，不做数值。
