### 1.3 M4 完成后可观察到的变化

- `?weather=lightRain`：闪电间隔 16–20s（长），天空闪白，能见度瞬时 3.5×（≤200m），敌人被照亮
- `?weather=heavyRain`：闪电间隔 8–12s（短），视觉/音效更强
- `?weather=clear` / `?weather=overcast`：**无闪电**（`lightningEnabled = false`）
- `?time=midnight&weather=heavyRain`：**无直升机**（`helicopterEnabled = midnight && !lightning`，`heavyRain.lightning = true`）
- `?time=midnight&weather=lightRain`：闪电全屏 `post.flash` 闪白；白天只天空提亮，不 `post.flash`
- 闪电后玩家在敌人 LOS 内：敌人 `investigate`，HUD 暴露标记
- 闪电后敌人进入光柱（若同时有直升机）：不叠加冷却（`forceExpose` 的 1.5s 冷却共享）

## 3. 新增文件：`src/effects/lightning.js`（约 150–220 行）

### 3.1 导出与结构

```js
export function createLightning(context) {
  return {
    enabled,                       // 由 environment._applyStatic 控制
    update(dt),                    // 调度 + 触发
    trigger(),                     // 手动触发（调试/展示）
    _schedule(),                   // 按 minInterval/maxInterval 随机
    _flash(),                      // 视觉 + 音效 + 回调 environment
    debug: { ... },                // 诊断
  };
}
```

### 3.2 内部状态

```js
state = {
  enabled: false,
  nextT: 0,                        // 距下次触发的秒数
  rng: context.rng.fork(),         // 独立随机源，可复现
  flashLight: null,                // 可选：瞬时 PointLight（M4 可不用，用 post.flash）
  flashT: 0,                       // 视觉衰减计时
};
```

### 3.3 调度（改造文档 2.4）

```js
function schedule() {
  const w = context.environment?.weather;
  const t = LIGHTNING_TIMING;
  let min = t.minInterval, max = t.maxInterval;
  if (w === "lightRain") { min = 16; max = 20; }
  else if (w === "heavyRain") { min = 8; max = 12; }
  state.nextT = min + state.rng() * (max - min);
}

function update(dt) {
  if (!state.enabled) return;
  if (context.game && context.game.state !== "playing" && context.game.state !== "showcase") return;
  state.nextT -= dt;
  if (state.nextT <= 0) {
    _flash();
    schedule();
  }
}
```

**要点**：

- `clear` / `overcast` 不触发：`_applyStatic` 检测 `lightningEnabled` 变化时 `setEnabled(false)`，`update` 直接 return。
- `lightRain` 间隔 16–20s，`heavyRain` 8–12s（`LIGHTNING_TIMING.minInterval = 8`，`maxInterval = 20` 是基础；M4 按天气覆盖）。
- `state.rng` 派生自 `context.rng.fork()`，固定 `seed` 可复现。
- `_schedule()` 在 `setEnabled(true)` 时首次调用，避免“刚启用就闪电”。

### 3.4 `_flash()`：视觉 + 音效 + 回调

```js
function _flash() {
  if (!state.enabled) return;
  // 1. 视觉：天空 uFlash（renderer 的 thunder 事件已有 uFlash 驱动，
  //    M4 用 lightning:flash 驱动 post.flash；白天只提亮天空）
  // 2. 音效：复用 audio.play("thunder", { delay: 随机 })
  // 3. 回调 environment._onLightningFlash()
  const isNight = (context.environment?.lampOn ?? 0) > 0.5;
  const allowPostFlash = isNight && (context.quality?.envFlash !== false);
  context.events?.emit("lightning:flash", {
    night: isNight,
    postFlash: allowPostFlash,
    intensity: context.environment?.weather === "heavyRain" ? 1.0 : 0.6,
  });
  // 音效
  if (context.audio?.play) {
    try {
      context.audio.play("thunder", {
        delay: 0.5 + state.rng() * 1.5,
        gain: context.environment?.weather === "heavyRain" ? 1.0 : 0.7,
      });
    } catch {}
  }
  // 回调 environment
  context.environment?._onLightningFlash?.();
}
```

**要点**：

- `lightning:flash` payload：`{ night, postFlash, intensity }`。订阅方（HUD、renderer）按此决定视觉。
- `audio.play("thunder", ...)` 复用现有 `thunder` 音效（`library.js` 已有 `thunder` 条目，`audio.js` 已订阅 `thunder` 事件）。**注意**：`audio.js` 的 `thunder` 事件订阅是 `ln("thunder", (te) => { ze("thunder", {...}) })`，所以 M4 应 **派发** **`thunder`** **事件**而不是直接 `audio.play("thunder")`，避免重复。修正：

```js
  context.events?.emit("thunder", {
    intensity: context.environment?.weather === "heavyRain" ? 1.0 : 0.6,
  });
```

`audio.js` 的 `thunder` 监听器会 `ze("thunder", { delay: 0.5 + (1-h)*2 + rand*0.6, gain: 0.35 + 0.65*h })`，自带延迟随机。**M4 不直接调** **`audio.play`，只派发** **`thunder`** **事件**。

- `renderer.js` 已订阅 `thunder` 事件更新 `w.t/w.power/w.value`（sky `uFlash`），M4 派发 `thunder` 后天空自动闪。**M4 不需要额外驱动 sky** **`uFlash`**。
- `_flash()` 的视觉分两层：
  - 天空 `uFlash`：由 `thunder` 事件驱动（renderer 已有）
  - 全屏 `post.flash`：由 `lightning:flash` 事件驱动（M4 新增，`postprocessing.js` 消费）
- 白天：`postFlash = false`，只有天空提亮；夜晚：`postFlash = true`。

### 3.5 `trigger()` 手动触发

```js

}
```

**4.1.4** **`scanLightningExpose()`（私有函数）**

```js
  function scanLightningExpose() {
    if (!context.enemies || !context.enemies.list) return;
    let p = context.player;
    if (!p || p.alive === false) return;
    let eye = p.eye || p.pos;
    let peak = visibility.lightningPeak;
    let eyeDist2 = peak * peak;
    for (let e of context.enemies.list) {
      if (!e.alive || !e.active || e.mode === "engage") continue;
      let dx = e.pos.x - p.pos.x, dy = e.pos.y - p.pos.y, dz = e.pos.z - p.pos.z;
      if (dx * dx + dy * dy + dz * dz > eyeDist2) continue;
      let sensor = e.sensor || e.pos;
      if (!context.physics.lineOfSight(sensor, eye)) continue;
      context.enemies.forceExpose(p.pos, "lightning", e);
    }
  }
```

**要点**：

- 粗筛距离平方，再 LOS，与 `helicopter.scanAndExpose` 对称。
- 跳过 `engage`：改造文档 4.5“AI：只写 `lastKnown` + 触发 `investigate`，不强制 `engage`”。
- `forceExpose` 的 1.5s 冷却由 `enemies` 侧维护，闪电与直升机共享。
- **不分帧**：9 敌人 × 1 次 LOS < 2ms，M4 单帧完成。

### 4.3 `src/enemies/walker.js` / `src/enemies/drone.js`（M4 新增）

**4.3.1 订阅** **`lightning:flash`**

改造文档 3.4 写“订阅 `lightning:flash` → 若 LOS 可达玩家则 `forceExpose`”。但 §4.2 说“全场遍历敌人：距离粗筛 + LOS”。这两者是**同一件事的两种视角**：

- `environment.scanLightningExpose`：从玩家视角，遍历敌人，判断“敌人能否看到玩家”
- `walker/drone` 订阅 `lightning:flash`：从敌人视角，判断“我能否看到玩家”

**M4 决策**：**只做** **`environment.scanLightningExpose`**，`walker.js` / `drone.js` **不改**。理由：

- `scanLightningExpose` 已覆盖“敌人 LOS 可达玩家”，无需敌人自己再判一次。
- `walker/drone` 订阅会导致同一闪电对同一敌人重复 `forceExpose`（虽然 1.5s 冷却会合并，但多一次 LOS 开销）。
- 改造文档 3.4 的“订阅 `lightning:flash`”是可选实现，§4.2 的“全场遍历”是主实现。M4 选主实现。

**若未来需要敌人视角的额外逻辑**（如“敌人被闪电照亮时的视觉反馈”），再在 `walker/drone` 加订阅，M4 不做。

## 5. 关键机制实现细节（改造文档第 7 章验收对照）

### 5.1 能见度脉冲（方案 B）

**M1 的** **`pushFrame`** **已有**：

```js
    if (visibility.lightningT > 0) {
      visibility.lightningT -= dt;
      visibility.current = visibility.lightningPeak;
    } else {
      visibility.current = damp(visibility.current, visibility.base, 3, dt);
    }
```

**M4 的** **`_onLightningFlash`** **设置**：

```js
      visibility.lightningT = Math.max(visibility.lightningT, LIGHTNING_TIMING.high);
      visibility.current = Math.max(visibility.current, visibility.lightningPeak);
```

**验收**：

- [ ] 闪电 0.8s 高能 + 0.8s damp 回落，不过冲：`lightningT = 0.8`，`current = peak`；`lightningT` 归零后 `damp(current, base, 3, dt)` 回落，3/s 的 lambda 约 0.33s 到 1/e，0.8s 到 \~0.9e^-2.4 ≈ 0.09，**不完全回落**——改造文档写“回落 `damp lambda ≈ 5`（约 0.8s 回落到 1/e）”。M1 的 `pushFrame` 用 `damp(current, base, 3, dt)`，lambda=3 比 5 慢。**M4 需改** **`pushFrame`** **的 lambda 为 5**，或 `_onLightningFlash` 设置一个 `visibility.dampLambda = 5` 临时值。**M4 决策**：改 `environment.pushFrame` 的 `visibility.current = damp(visibility.current, visibility.base, 3, dt)` 为 `5`，与改造文档一致。

**4.10 修正**：M4 需改 `core/environment.js` 的 `pushFrame`：

```js
    if (visibility.lightningT > 0) {
      visibility.lightningT -= dt;
      visibility.current = visibility.lightningPeak;
    } else {
      visibility.current = damp(visibility.current, visibility.base, 5, dt);  // M4: 3 → 5
    }
```

### 5.2 连续闪电取 max 不叠加

`_onLightningFlash` 的 `lightningT = Math.max(lightningT, high)` 和 `current = Math.max(current, peak)`，连续闪电时 `lightningT` 重置为 0.8，`current` 保持 `peak`（不叠加到 2×peak）。✓

### 5.3 敌人视觉半径 ≤ 玩家能见距离

M2 的 `effectiveSightRadius = min(visibility, baseRadius * visualAlert)`，闪电时 `visibility = 200`，`min(200, 45) = 45`，**视觉半径不变**。这是 M2 决策 A 的预期：`sightRange = 45 < visibility = 200`，闪电不改变敌人视觉半径。**M4 不改**。

### 5.4 白天闪电不触发 `post.flash`

`_flash` 的 `isNight = (context.environment?.lampOn ?? 0) > 0.5`，`postFlash = isNight && envFlash !== false`。白天 `lampOn = 0.0`（noon）或 `0.4`（dawn），`postFlash = false`。✓

### 5.5 墙后不被闪电暴露

`scanLightningExpose` 的 `context.physics.lineOfSight(sensor, eye)` 判定，墙后 `lineOfSight` 返回 `false`，不暴露。✓
